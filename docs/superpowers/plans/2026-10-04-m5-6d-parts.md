# M5.6d explorer parts implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development`. This plan is a design brief: it
> fixes the decisions, the public surface and the tests that must exist, and
> the implementer writes the code test first.

**Goal:** Make the explorer usable: `ExplorerRoot` with its state, the named
parts, `useExplorer`, the preassembled `DagrExplorer`, the optional
stylesheet, and the public entry that exports them.

**Architecture:** `ExplorerRoot` validates and lays out the data, owns the
state (controllable view and selection; internal query, trace, drawer), and
provides it through one context. Each part reads that context. The public
`ExplorerViewport` wraps the internal `ViewportSurface` from M5.6c-2.
`DagrExplorer` is composed only from the public parts.

**Tech Stack:** TypeScript, React 18 and 19, Vitest with jsdom

**Spec:** `docs/superpowers/specs/2026-10-03-dagr-explorer-design.md`. This
slice implements, in full: "Composition" (Parts, `ExplorerRoot` props, State,
Slots, Labels, Styling), "Search", "Drawer", and `ExplorerContextError` from
"Errors". Read those sections first: they are the requirements, and this brief
only adds what they leave open.

## Decisions this brief makes

- **One context**, `ExplorerContext`, holding the root's derived data and
  state and the `ExplorerApi` methods. It is internal; `useExplorer()` is the
  public way in and throws `ExplorerContextError` (`OUTSIDE_EXPLORER`) outside
  a root.
- **Data props are a union** with `never` guards, as the spec says. The
  shorthand view has id `'default'` and the root's `label` as its label.
- **Validation and layout** run in the root, in render, memoized by
  `layoutKey` (internal, from `layout.ts`) and `strictGroups`. A data error is
  thrown in render, so an error boundary catches it. Only the active view is
  laid out; all views are validated with `validateViews`.
- **Controlled values** follow the spec's State section exactly: internal
  changes call the callback and render nothing new until the prop changes; an
  unknown controlled value renders as its fallback (no selection; the first
  view) with no corrective callback.
- **`ExplorerViewport`** registers with the root in an effect with cleanup. A
  second registration throws `ExplorerContextError` (`SECOND_VIEWPORT`) from
  that effect. It passes `selectedId`, dimming (from the query and from trace)
  and pins to `ViewportSurface`, and wires `onNodeActivate` to `inspect` and
  `onNodeZoom` to `focusNode`. Camera methods in `ExplorerApi` call the
  surface's controls; before a viewport mounts they are no-ops.
- **Dimming**: a non-empty query dims every node that does not match. Trace,
  with a selection, dims every node that is not the selected node or adjacent
  to it. Both together dim the union.
- **`ExplorerDetails`** renders nothing when the drawer is closed. Its slot
  receives `{ node, connections, inspect }`, where `connections` is the edges
  touching the node with the other node resolved. The default body shows the
  label and a connection list of buttons. Focus restoration and `Escape`
  precedence follow the spec's Drawer section, with the drawer's opener
  recorded by `inspect(id, trigger?)`.
- **`ExplorerSearch`** is a labeled input, a live match count, and a result
  list of buttons. The list stays mounted while the drawer is open.
- **`ExplorerToolbar`**: zoom out, a zoom readout (percent, updated from the
  camera without re-rendering the root), zoom in, fit, and zoom to selected
  (disabled without a selection).
- **`DagrExplorer`** composes, in this order: views, search, trace toggle,
  viewport, details, toolbar. Its props are the root's props plus
  `renderNode`, `renderDetails`, `renderConnection`, `renderViews`, `tiers`,
  `maxOverlayNodes`, `base`, `nodeAriaLabel`.
- **`styles.css`** lives at the package root, is not imported by any module,
  and styles only through `[data-dagr-explorer]` hooks and the
  `--dagr-explorer-*` variables the spec lists. It must look reasonable on a
  light page with no other CSS.

## Review focus

- **Controlled selection with an id the data lacks.** No drawer, no throw, no
  callback loop.
- **The selected node is removed from the data while the drawer is open.**
  Selection clears (uncontrolled) or the callback fires (controlled), the
  drawer closes, and focus goes to the opener or the search input.
- **Two explorers on one page.** Independent state; no shared ids; one
  `ExplorerViewport` each is fine.
- **A view switch while the drawer is open and a query is typed.** Query,
  trace, drawer and camera reset; selection comes from `selectOnViewChange`.
- **`useExplorer` outside a root, and a part outside a root.** Both throw
  `OUTSIDE_EXPLORER` with a message naming the part.
- **Escape precedence** in the search field, inside the graph, and in the
  drawer.

## Tests that must exist

Root and state: uncontrolled and controlled view and selection; the shorthand;
passing both shapes is a type error (a `@ts-expect-error` test); an unknown
controlled id; `defaultSelectedId` read once; `selectOnViewChange`; a view
removed while active; a data error reaches an error boundary; `apiRef` methods
(`select`, `inspect`, `closeDetails`, `selectView`, `setQuery`, `setTrace`,
`fit`, `zoomBy`, `focusNode`, `reveal`), including before the viewport mounts.

Parts: each part renders inside a root and throws outside one; a second
`ExplorerViewport` throws `SECOND_VIEWPORT` and a remount (StrictMode) does
not; `ExplorerViews` renders nothing for one view and a slot replaces it;
search tokens, count, Enter, Escape, choosing a result; dimming by query, by
trace, by both; the drawer's slot, default body, connection buttons keeping
the opener, focus restoration, scroll to top on a new node, every Escape case;
the toolbar's buttons and readout; `labels` replace every default string
(assert by rendering with a labels object whose every value is a sentinel and
finding no default text).

`DagrExplorer`: composes all parts; slots are forwarded and typed from
`views` (a type test that `renderNode` receives the caller's node type).

Surface: `test/index.test.ts` pins the twenty-one runtime names. The packaging
gate passes with `styles.css` in the tarball.

All component tests run under both React configs.

## Out of scope

Roving focus, arrow-key node navigation, `reveal` on keyboard focus, and server
rendering tests are M5.6e. Docs pages, demos, the bench, browser verification,
removing `"private"` and the umbrella subpath are M5.6f.

## Amendments during execution

The API design review and the code review of this slice changed what the
brief says in several places. The spec's amendment 15 is the authority where
they differ from the text above.

- **22 runtime names, not 21:** `useExplorerApi` was added.
- **Two contexts, not one:** the methods live in a second context whose value
  never changes, so a method-only consumer never re-renders.
- **`ExplorerCamera` and `ExplorerVisibleSet` are exported as types,** because
  public signatures return them.
- **`DagrExplorer` nests `ExplorerDetails` inside `ExplorerViewport`,** which
  now takes `children`, so the order "viewport, details" no longer describes
  the tree.
- **The search list is capped** by `maxResults` (default 50), with a
  `moreMatches` line.
- **Labels:** kept by value; `showDetails` and `hideDetails` dropped;
  `moreMatches` and `inGroup` added.
- **Late data is not a view switch.**
- **A part's `style` is applied over its own sizing**, and the viewport keeps
  the `position` and `overflow` it needs.
- **Focus falls back to the root element,** and **`Escape` closes the drawer
  from anywhere in the root.**
