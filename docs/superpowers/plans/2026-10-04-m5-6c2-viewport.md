# M5.6c-2 explorer viewport implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development`. This plan is a design brief, not a
> transcript: it fixes the decisions, the interfaces and the tests that must
> exist, and the implementer writes the code test first.

**Goal:** Render a laid-out view: a pannable, zoomable surface with an SVG base
layer and a windowed DOM overlay, driven by the pure core from M5.6c-1.

**Architecture:** One internal, prop-driven component, `ViewportSurface`, and
one hook, `useExplorerCamera`. The hook owns the animation frame, the resize
observer and the gestures, and holds no arithmetic: it calls `camera.ts`. The
surface writes one transform per frame and re-renders only when the visible
set changes. `ExplorerRoot` and the public `ExplorerViewport` part are M5.6d,
which wraps this surface with context.

**Tech Stack:** TypeScript, React 18 and 19, Vitest with jsdom

**Spec:** `docs/superpowers/specs/2026-10-03-dagr-explorer-design.md`, sections
"Tiers and virtualization", "Camera and pointer", "Server rendering".

## Global constraints

- Everything in this slice is INTERNAL. `src/index.ts` and
  `test/index.test.ts` do not change. The public parts are M5.6d.
- Never import `@prnt/dagr-render` (the full entry), `@prnt/dagr-react`, or
  `three`. `test/imports.test.ts` must keep passing.
- React 18 and 19: no `use`, no `ref` as a prop, no React 19 only API or type.
- All arithmetic comes from `src/camera.ts` and `src/visible-set.ts`. The hook
  and the component add none.
- The camera never causes a React render. A frame is one `style.transform`
  write on the plane. React renders only when `sameVisibleSet` is false, or a
  prop changes.
- No per-node listeners at any tier. Pointer handling is delegated on the
  viewport.
- Vector content is never forced onto a composited layer: no `will-change`,
  no `translateZ`.
- No em-dashes in any prose. Commits: conventional subject, author
  `Dagr Agent <agent@prnt.design>`, trailer
  `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## Review focus

- **Unmount during a flight.** The animation frame, the resize observer and
  every listener are removed, and a late frame writes nothing.
- **A viewport measured at 0 by 0** (hidden tab, `display: none`). No limits,
  no fit, no throw. It fits when it gets a size.
- **A layout swapped while panning.** Limits and the visible set rebuild, and
  the camera refits.
- **A drag that starts on a node.** It pans, and the click that would follow
  is suppressed, so the node is not activated.
- **`maxOverlayNodes` or a tier gate that is `NaN` or negative.** Falls back to
  the default, with no throw.
- **StrictMode's double effect.** Mount, cleanup, mount leaves exactly one set
  of listeners and one frame loop.

## Behavior

**DOM shape.**

```
div[data-dagr-explorer="viewport"][role="region"][aria-label][tabindex="-1"]
  div[data-dagr-explorer="plane"]            width, height from the layout
    <base.Layer />                            when base.space is 'plane'
    button[data-dagr-explorer="node"] * n     overlay nodes only
```

- The viewport's inline style: `position: relative`, `overflow: hidden`,
  `height: var(--dagr-explorer-height, 480px)`, and `touch-action: none` only
  while it contains focus.
- The plane's inline style: `position: absolute`, `transform-origin: 0 0`,
  `visibility: hidden` until the first fit, then visible.
- Each overlay node is a `button` with `type="button"`, `tabIndex={-1}`
  (roving focus is M5.6e), `data-node-id`, `data-tier`, `data-selected`,
  `data-dimmed`, `aria-pressed`, an accessible name (the label and
  "in <group label>" for each group it is in, or `nodeAriaLabel`), and inline
  `position: absolute; left; top; width; height` from its box. It renders
  `renderNode(node, context)`, or the label by default.
- The plane carries `--dagr-explorer-inv-zoom`, written only when the scale
  changes, and the viewport carries `data-dragging` during a drag.

**Camera hook.** A port of `docs/src/components/GraphViewport/useGraphCamera.ts`
(read it), with its arithmetic replaced by calls to `src/camera.ts`:

- One `requestAnimationFrame` loop eases `current` toward `target` with
  `easeCamera` and stops when `cameraSettled`. A target is constrained when
  set, and the eased camera again when drawn.
- Under `prefers-reduced-motion: reduce`, a change applies immediately.
- A `ResizeObserver` on the viewport rebuilds the limits and refits.
- Wheel: zooms only while focus is inside the viewport, anchored at the
  pointer, factor `Math.exp(-clamp(deltaY * unit, -150, 150) * 0.002)`.
  `Ctrl` or `Command` wheel is left to the browser. `Shift` wheel pans
  horizontally. An unfocused wheel is not prevented.
- Pointer: a primary-button press records a start. Past 5 CSS pixels it
  becomes a pan: focus the viewport, capture the pointer, set
  `data-dragging`, and suppress the `click` and `dblclick` that follow. A
  press on a `button`, link or form control that is not a
  `[data-dagr-explorer="node"]` does not start a drag. On touch, a press
  while the viewport does not contain focus only focuses it.
- Keys on the viewport: `+` or `=` zoom in by 1.25, `-` zooms out by 0.8, `0`
  fits, arrows pan by 60, `Escape` blurs. Keys from an input are ignored.
- Before the viewport has a size there are no limits: controls are no-ops and
  `getCamera()` is `null`.

**Visible set.** On each frame, `computeVisibleSet(index, camera, viewport,
{ tiers, maxOverlayNodes, pinned })`. Keep the previous result by reference
when `sameVisibleSet` says so, and set state only otherwise. `selectedId`, when
set and present in the layout, is added to `pinned`. A `tiers` or
`maxOverlayNodes` value that is not a finite, non-negative number falls back
to the default.

**Activation.** One `click` listener on the viewport. A click inside an
overlay node activates that node with the button as trigger. A click on the
plane elsewhere resolves through `screenToWorld` and `nodeAtPoint`: on a mark
it activates that node with a `null` trigger. A click on empty space focuses
the viewport and activates nothing. `dblclick` calls `onNodeZoom` the same
way. `Enter` and `Space` on a focused node button activate it natively.

**SVG base.** `svgBase: ExplorerBase` with `space: 'plane'`. An `svg` sized to
the layout, `aria-hidden`, containing: one `rect` per group with its label as
`text`, one `path` per id in `visible.edges` (`M`/`L` through its route
points, `marker-end` arrowhead from a `marker` with a `useId`-derived id,
`stroke-dasharray` when `dash`, stroke from `edge.color`), and one `rect` per
id in `visible.baseNodes` (fill from `node.color`). `data-dimmed` on marks and
edges from `emphasis`. An edge is dimmed when either end is dimmed.

## Tests that must exist

Use fake timers and a manual `requestAnimationFrame` stub so frames are
stepped deterministically. Give the viewport a size with the resize helper.

`use-explorer-camera.test.tsx`: fits on first size and makes the plane
visible; no fit and no throw at 0 by 0, then fits when sized; wheel does
nothing unfocused and is not prevented; wheel zooms when focused and keeps
the world point under the pointer; `Ctrl` wheel is not prevented; a drag past
5 pixels pans and suppresses the click; a press released within 5 pixels does
not pan; keys zoom, fit and pan; reduced motion applies in one frame;
`focusBox` and `revealBox` reach the camera `camera.ts` computes; a resize
refits; unmount cancels the frame and removes listeners, and a late frame
writes nothing; StrictMode mounts leave one loop.

`svg-base.test.tsx`: draws only `visible.edges` and `visible.baseNodes`; group
rectangles and labels; dash, color and arrowhead; dimming of marks and of
edges with a dimmed end; an edge with an empty route draws no path.

`viewport-surface.test.tsx`: mounts overlay nodes only for the visible set, at
the right tier and box; a node under the summary gate has no button; the
selected node is mounted when off screen; React does not re-render for a pan
inside the overscan margin (count renders of a `renderNode` spy); a zoom
across a gate changes `data-tier`; the cap holds with 500 nodes in view
(at most `maxOverlayNodes` plus pins); a click on a node button activates
with the button as trigger; a click on a mark activates with `null`; a click
on empty space activates nothing; a drag that starts on a node does not
activate; `renderNode` receives `tier`, `selected`, `dimmed`; the accessible
name includes group membership; a swapped layout refits and rebuilds; bad
`tiers` and `maxOverlayNodes` fall back; nothing is rendered that names a
host framework.

All three files pass under both vitest configs (React 19 and React 18).

## Amendments during execution

A code review and a graphics-and-feel review on 2026-10-04 changed what this
brief says in several places. The spec's amendment 14 and the fix brief are
the authority where they differ from the text above.

- **`will-change`.** The plane is composited while the camera moves or a drag
  is active, and not at rest, so motion is smooth and resting text is sharp.
  The global constraint "no `will-change`" is superseded.
- **The seam.** `ExplorerBaseProps` also carries `camera`, a source with
  `get()` and `subscribe(listener)`, whose listeners are called in the frame
  the plane transform is written. Its `view` is `Omit<ExplorerView, 'layout'>`.
- **Keeping the user's place.** A resize and a layout swap keep the world point
  at the viewport center and the scale, and refit only when the camera was at
  fit. The behavior and review-focus lines that say they refit are superseded.
- **Pinch.** A `Ctrl` wheel while the viewport has focus zooms the graph, and
  two touches pinch. `Command` and any unfocused wheel stay the browser's. The
  line saying `Ctrl` or `Command` wheel is left to the browser is superseded.
- **A drag is 1:1**, with no ease. The first tap on touch only focuses.
- **Marker ids** are derived from the escaped color, not from `useId`, so two
  React roots cannot collide.
- **The scan is skipped** while the scale is unchanged and the view stays
  inside the last scanned rect, expanded by half the overscan.
