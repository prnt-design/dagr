# M5.6f-1 explorer docs, demos and bench implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development`. This plan is a design brief.

**Goal:** Document the explorer on the docs site with live demos, and add the
benches the spec asks for, so the browser checks in M5.6f-2 have pages to
drive.

**Architecture:** A docs page, `docs/docs/explorer.md`, embeds two client-only
demo components. A bench file in `packages/explorer/bench` measures the
visible set and layout in Node. Nothing in `packages/explorer/src` changes.

**Spec:** `docs/superpowers/specs/2026-10-03-dagr-explorer-design.md`,
sections "Docs" and "Tests" (the bench paragraph), and "Amendments".

M5.6f is split: this is the docs, demos and bench. Browser validation, the
measured SVG ceiling, the umbrella subpath and removing `"private"` are
M5.6f-2.

## Global constraints

- **No change under `packages/explorer/src`**, and no change to any
  `package.json` except `docs/package.json` (add `@prnt/dagr-explorer` as
  `workspace:*`) and `packages/explorer/package.json` (a `bench` script only,
  matching how `packages/react` runs its benches). If a demo exposes a bug in
  the package, stop and report it with a reproduction: that is M5.6f-2's.
- The docs site is Docusaurus 3 on React 19. Demos are client-only where they
  must be (read how `docs/src/components/LivingDemo` and `LiveLayout` are
  embedded and copy the pattern). The docs build (`pnpm build`) must pass.
- The demos use only the public entry, `@prnt/dagr-explorer`, and
  `@prnt/dagr-explorer/styles.css`. No deep imports.
- No em-dashes in any prose. Commits: author `Dagr Agent <agent@prnt.design>`,
  trailer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## What to build

1. **`docs/src/components/ExplorerDemo/`**
   - `ArchitectureDemo`: `DagrExplorer` over a small architecture-style graph
     defined in the component's own data file: two or three views (for
     example an overview and a trust view), 10 to 25 nodes with a `kind`,
     groups, a few parallel and dashed edges, a custom `renderNode` that shows
     the kind and label at the `rich` tier and only the label at `summary`, a
     `renderDetails` with a few facts, and `searchText` that includes `kind`.
     Original, invented data: nothing from any other repository.
   - `LargeGraphDemo`: `DagrExplorer` over a synthetic graph of 2,000 nodes,
     generated deterministically (a seeded generator in the component's data
     file), shaped like a layered system so the layout is readable. A small
     readout below it shows the node and edge counts and the number of overlay
     node elements currently mounted (count `[data-dagr-explorer="node"]` on a
     timer or a `MutationObserver`). This readout is what M5.6f-2's browser
     check reads to prove the cap holds.
   - Both import `@prnt/dagr-explorer/styles.css` and map the stylesheet's
     variables to the Docusaurus theme (`--ifm-*`) in a CSS module, so the
     demos follow the site's light and dark modes. This mapping is the worked
     example of theming for a host.
   - Each demo root carries a stable `data-demo="architecture"` /
     `data-demo="large"` attribute for the browser checks.
2. **`docs/docs/explorer.md`**: the guide. Sections: what it is (one
   paragraph), install (and that React 18 sites use `@prnt/dagr-explorer`
   directly), the `DagrExplorer` example, the live architecture demo, the
   parts and custom layout, `useExplorer` and `useExplorerApi`, labels,
   theming with the stylesheet and its variables (show the `--ifm-*` mapping),
   tiers and virtualization (what is mounted and why, `maxOverlayNodes`,
   pins), keyboard and screen readers (one tab stop, search reaches every
   node), server rendering, the experimental base-layer seam, the live large
   demo, and limits (no browser-measured ceiling yet: M5.6f-2 fills it in;
   self loops not drawn; groups do not affect layout). Check every claim
   against the package's README and code. Give it a `sidebar_position` after
   `node-groups`.
3. **`packages/explorer/bench/explorer.bench.ts`**, run by the package's
   `bench` script the way `packages/react/bench` is: `computeVisibleSet` at
   1,000 and 10,000 nodes (fit, and zoomed in), and `layoutView` at 1,000
   nodes. Import from `../src/...` (benches may reach internals). Per
   `bench/README.md`, new entries report as `new` and are NOT added to
   `bench/baseline.json`: recording them is the maintainer's call. Confirm
   `pnpm bench:ci` still passes with the new entries reported as `new`.
4. **Tests:** a docs vitest test (see `docs/vitest.config.ts`) that the
   synthetic generator is deterministic and produces 2,000 nodes that pass
   `validateView`, and that the architecture data passes `validateViews`.
5. **Roadmap and changelog:** nothing to check off yet (M5.6f is not done).
   Add one line to `packages/explorer/CHANGELOG.md` noting the docs page and
   benches.

## Out of scope

Browser checks, screenshots, the measured ceiling, the umbrella subpath,
removing `"private"`, publishing: M5.6f-2 and after.
