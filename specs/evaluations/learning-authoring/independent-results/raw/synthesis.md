# Six independent authoring outputs: bounded synthesis

## Outcome

All six fresh outputs compile/build against published Dagr Explorer 0.2.0.
All twelve default-view desktop/phone-emulated reading flows completed without
page errors or document overflow. Content quality varies despite that technical
success. Recommend two narrow additions to the canonical skill: audit universal
claims and declarations versus verified behavior; distinguish optional learning
order and trace workflow branches/retries/repeated checks. proposed-skill.patch
makes these additions reviewable, without changing the runtime or examples.
It is a proposal artifact, not an applied or tested canonical change.

PR269 already merged the earlier same-context pilot and neutral input packets.
The independent study is separate evidence. No task completion, publication,
new trials, or merge is claimed here.

## Protocol and provenance

Three briefs, baseline/guided per brief, six fresh isolated sessions, serially
coordinated by the parent with no forked pilot context. Equal requested runtime
claude, model opus, effort medium. launch-records.json retains exact submitted
prompts, successful session IDs, cwd and per-input hashes. Its provenance is
coordinator reconstruction verbatim from tool-call arguments, not a server
session export. opus is a provider alias; immutable backend revision is unknown.
All six input hash sets were verified against preserved cwd copies. Content
source commit and canonical skill pin: ccb66cad9dfc3baf650d65338e2bb2ae6c38aae2.
Baseline had neutral brief/source plus equal public 0.2.0 API access; guided
additionally had pinned skill/reference. Source access notes remain per arm.

The failed first codebase launch created no session and is excluded. The six
successful sessions are the launch record's records. Evaluator knows labels,
has seen the skill and pilot defects, and is not an independent human learner.
Only one output per condition/brief, no randomization or replication. The
process-guided author performed a pre-save Python quote/endpoint check;
checking conditions were not identical. These limitations rule out causal
or statistical effectiveness claims. No human learner success was measured.

Specific observations:

- Codebase guided adds useful explanation/why/source-field structure, but
  calls graph uniquely free of other Dagr dependencies while render is too.
  It also overstates what manifests establish about build/publication flow.
  Baseline stays closer to manifest facts but uses version ranges as edge
  labels and presents mostly raw facts in details.
- Both prerequisite arms present optional groups as required for views.
  Guided starts with 9 nodes versus baseline's 23 and includes explanatory
  keywords. Static evaluation of exact searchText expressions finds the
  MISSING_EDGE_ENDPOINT concept only in guided, although both teach it in
  details. Ordinary search flows are browser-tested; that domain query is
  an expression-level check, not a separate browser assertion.
- Process baseline omits the red-CI return edge to retain an acyclic graph;
  guided preserves it. Both shortcut the local-gate path after main moves.
  All quoted passages match source under whitespace normalization, showing
  why quote checks alone do not establish a correct process graph.

These defects justify the proposed skill additions as targeted guardrails.
They do not prove the additions will prevent future defects. The current
reference example need not change; the observed failures concern grounding
and semantic modeling, not a demonstrated error in that example.

## Validation and preserved evidence

Originals and their author manifests are under each arm's initial/. All twelve
initial source files were verified; no content repairs were made. Separate
consumer-initial/ copies hold host entry/config plus initial copied sources.
Strict tsc and Vite build logs/exit files are retained per arm, all exit 0.
Package-lock.json captures published dependencies; node_modules resolved to
an external consumer, never workspace aliases. No distribution reinstall
study was performed. Structure JSON checks unique IDs/endpoints in every view.

Each arm ran desktop 1280x800 and 390x844 touch emulation, scale 2, reduced
motion enabled, with search/inspect/follow/close, empty search, keyboard
inspect/Escape and outline. Browser JSON records actual followed nodes,
focus after close, errors and overflow; screenshots capture follow/outline.
Browsers, contexts and servers closed under shared compute lifetime wrappers.
Per-pair reports identify untested controls/view switches. This is technical
agent task completion, not evidence that learners find/explain/follow correctly.

No real-device or screen-reader study, contrast ratios, full rich-node clipping,
keyboard connection-follow, all authored control states or animation analysis.
Partial accessibility/rich scores reflect those missing checks. No such
coverage is implied by successful compilation or screenshots.

Evaluator harness incidents: the codebase structure checker initially used
codebaseData.ts instead of codebase-data.ts and failed ENOENT. Correcting the
checker path produced successful structure results; author source was not
changed. The process harness accepts both h2 and h3 detail titles. Neither
is an initial author compile failure or a repair. No initial compile/build
or default-view browser failure occurred in the six independent outputs.
